# Fidelity matrix

Every lab declares the fidelities it supports (`fidelity.supported`) and a
default. The router picks the requested level when the lab supports it and the
runtime is available, otherwise falls back (F2 → F1 → F0) and tells the
learner why (pool exhausted, quota reached, runtime not configured).

| Level | What runs the commands | Used for | Grading source |
|---|---|---|---|
| **F0** simulator | `internal/sim` + `internal/cli`, deterministic per seed | every lab; incidents, company, chaos, what-if | simulator state |
| **F1** emulators | F0 control plane + emulators for data planes | Pub/Sub and object storage data paths, Kubernetes API | simulator state mirrored from the emulator calls |
| **F2** real GCP | `gcloud`/`gsutil`/`bq`/`kubectl`/`terraform` against a leased sandbox project, impersonating the learner identity | final checks, capstones, "does it really work" | snapshot of the real project (`GcloudDriver.Snapshot`) |

## Service coverage

| Service | F0 | F1 | F2 | Notes on F0 fidelity |
|---|---|---|---|---|
| IAM (roles, custom roles, conditions, SAs, impersonation, deny via org policy) | ✅ | F0 | ✅ | effective-permission evaluation incl. folder/org inheritance |
| Resource hierarchy and org policies | ✅ | F0 | folder-level only | PAP, location, external IP, domain restriction |
| VPC, subnets, firewall, routes, NAT, peering, VPN/HA VPN | ✅ | F0 | ✅ | packet path evaluated per request (`why`) |
| Load balancing, health checks, Cloud Armor | ✅ | F0 | ✅ | health-check source ranges enforced |
| Compute Engine, MIGs (zonal/regional), autoscaling | ✅ | F0 | ✅ | guest OS model: files, permissions, disks, services, users |
| Cloud Run, Cloud Build, Artifact Registry, Cloud Deploy | ✅ | F0 | ✅ | image behaviours drive runtime symptoms |
| Cloud Storage | ✅ | ✅ objects (fake-gcs) | ✅ | IAM, PAP, UBLA, lifecycle stay in F0 (not implemented by fake-gcs) |
| Pub/Sub | ✅ | ✅ (official emulator) | ✅ | IAM enforced by F0 before the emulator call |
| Cloud SQL | ✅ | F0 | ✅ | flags, backups, HA, connections, import/export |
| BigQuery | ✅ (dry-run bytes) | F0 | ✅ | cost checks use scanned bytes |
| GKE / Kubernetes | ✅ | ✅ (kind) | ✅ | RBAC, OOM, PVCs, HPA, rollouts |
| Logging, Monitoring, alerting, SCC | ✅ | F0 | ✅ | logs and metrics generated by synthetic traffic |
| Secret Manager, KMS | ✅ | F0 | ✅ | |
| Billing, budgets, recommender | ✅ | F0 | budgets only | FinOps labs use bill snapshots |
| Terraform | ✅ subset (HCL parser, plan/apply/import/state) | F0 | ✅ real Terraform | drift and `prevent_destroy` simulated |

## Known limits

- F0 is a model, not Google Cloud: error texts and edge cases follow the
  public documentation, and anything a lab relies on is covered by lab CI.
- F1 needs the emulator endpoints (`PUBSUB_EMULATOR_HOST`,
  `STORAGE_EMULATOR_HOST`, `KIND_KUBECONFIG`); without them F1 labs fall back to F0.
- F2 sessions are limited per learner and month (`F2_MONTHLY`) and by the pool
  size; the janitor reclaims expired leases and quarantines projects that do
  not come back clean.
